# NAVER MYBOX

This backend uses the [MYBOX Open API](https://developers.mybox.naver.com/docs/dms_root).
Paths have the form `remote:path/to/folder`.

## Configuration

Create a personal access token in MYBOX web settings under **Account and
personal access token management**. See the
[official setup guide](https://developers.mybox.naver.com/getting-started).
Run `rclone config`, create a remote, select `mybox` (NAVER MYBOX), and enter
the token at the `access_token` prompt.

The resulting configuration is:

```ini
[mybox]
type = mybox
access_token = YOUR_PERSONAL_ACCESS_TOKEN
```

The token grants access to your account. Protect your configuration file, or
use rclone's configuration encryption. Tokens expire; replace an expired or
revoked token in the configuration with a newly generated one.

Examples:

```sh
rclone lsd mybox:
rclone ls mybox:Documents
rclone copy ./photos mybox:Photos
rclone copy mybox:Documents ./download
rclone mkdir mybox:Backup
rclone about mybox:
```

## Supported operations

The backend lists files and folders with cursor pagination, uploads and
overwrites files, downloads files, creates folders, deletes files and empty
folders, renames files and folders within their current parent, and reports
account storage usage. Downloads obtain a fresh URL on
each open. Transfer URLs do not receive the personal access token.

Deletion moves items to the MYBOX trash. Removing a nonempty directory with
`rmdir` fails. `purge` uses rclone's recursive deletion fallback.

## Limitations

- MYBOX does not expose file checksums. Size and modification time are used
  for comparisons.
- Uploads require a known file size. Unknown-length streaming uploads and
  resumable uploads are not implemented.
- Modification time is sent during upload, with second precision. Changing
  it on an existing file requires re-uploading that file.
- Server-side renaming of files and directories within the same parent is
  supported, including on mounts. Moving to another parent directory,
  server-side copy, and public links are not implemented. Rclone can use
  its transfer fallbacks for moves between directories.
- MYBOX rejects names starting with a period. The default encoding stores
  the leading period as a fullwidth period and restores it in rclone listings.
  This allows macOS `.DS_Store` and `._` sidecar files to be uploaded. The
  encoded name is visible in the MYBOX web interface.
- Password-protected folders and folders shared with you are not exposed by
  the Open API.
- API limits depend on the MYBOX plan. Requests are paced and temporary API
  failures are retried. Single-use file transfers are not retried internally;
  rclone can retry the whole transfer with a new URL. Use `--tpslimit` to
  reduce the request rate further if needed.

## Testing

HTTP mock tests cover the API protocol without credentials. To run the
standard live backend suite, configure a dedicated remote named `TestMybox`
and run `go test -v ./backend/mybox -run TestIntegration`.

A live account smoke test on 2026-09-28 verified listing, quota reporting,
nested folders, Korean filenames, upload/download byte equality, timestamp
preservation, range downloads, overwrites, empty files, and deletion to trash.
File and directory renames and leading-period filename encoding were also
verified against a live account.
The full standard backend integration suite and exhaustive filename
restrictions have not yet been verified against MYBOX.
